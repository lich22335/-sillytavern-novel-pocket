# 小说随身库 · Novel Pocket v0.3.1

SillyTavern 1.19 的本地小说扩展。导入 TXT/Markdown 一次，在不同角色聊天里选同一本书，每个聊天分别保存自己的剧情进度。支持顺序阅读和关键词检索，不使用额外摘要、Embedding API 或额外 AI 账号。

## 安装和更新

在酒馆「扩展 → 安装扩展」粘贴：

`https://github.com/lich22335/-sillytavern-novel-pocket`

已有用户更新扩展后刷新页面，管理窗口标题显示 `0.3.1`。入口是扩展设置中的「小说随身库 · 打开管理窗口」，同时提供浮动「小说」按钮。原有小说数据库保留，**无需重新上传**。

## 跟着原著玩

1. 打开一个已保存的角色聊天，进入小说管理窗口。
2. 上传 TXT，或在「本聊天使用的小说」选择之前导入的书。换角色卡只需重新选书，不要重复上传。
3. 用「按章节找片段」或输入段号点「查看」，通过上一段／下一段浏览完整原文。也可展开「用原文查找位置」粘贴场景结尾，切换定位候选看完整预览。确定后点「从预览的第 N 段开始」，才设为当前剧情起点并启用顺序模式。浏览本身不会改变进度。
4. 完整章节仍保存在小说库和预览中。给AI的原文默认每次最多4500字符：优先自然段边界，超长自然段退到句末，连标点都没有才按限额拆成连续批次，剩余位置会保留，不丢弃后文。每批标注段号、offset、end_offset及总长度。参考多个章节也共享同一个字符上限。
5. 在正常发送聊天消息时，若酒馆工具调用及中转均支持，AI 可调用读取工具获取后续，并在认为当前批剧情结束时提交章内进度。当前章尚未读完时只能在同一章内推进；读到章末才进入下一章。单纯预读不会改变进度。
6. 不支持工具调用、AI不调用工具或判断不合你意时，用「AI上一批 / AI下一批」手动调整发送位置；它与下方整章浏览的「上一段 / 下一段」分开。整章浏览不改进度，点「从这里开始」会从该章开头重新开始。也可关闭AI自动推进。

普通酒馆已支持工具接口，但需要在**聊天补全设置开启工具调用 / Function calling**，且中转正确转发工具参数和结果。窗口会显示酒馆当前是否支持；这不能证明具体中转一定可用。推荐用正常「发送」验证，酒馆自身的「继续生成 / continue」模式不会发起原生工具调用。

AI工具使用当前聊天模型，不调用另一个模型。普通注入的原文默认最多4500字符；同一条玩家消息通过工具额外读取的原文，累计也最多4500字符，防止多次调用无限取文。设置的字符数是原文长度，不含少量标题、位置标记和工具JSON，也不是Token数。重复生成同一条玩家消息不重置工具额度，下一条玩家消息才重置。工具返回与后续回复仍消耗正常用量，酒馆保留的旧工具结果、聊天记录、世界书和预设不在此限额内，整段上下文仍需用户控制。

## 自由探索与预设

切换「关键词检索」时按最近对话匹配人物、地点、事件，默认五段，可能来自不同章节；这些段也标注全文序号。它不是语义向量检索，命中率有限。

默认原文插在聊天历史开头，即前置预设之后、聊天正文之前，作为单独背景参考，不再附加剧情控制、隐瞒检索或写作格式要求。可改为最近玩家发言前的独立用户参考消息，不直接修改你的原话、角色卡或预设。最终顺序受酒馆提示词管理器设置影响；原著文风仍可能影响生成，位置调整不能保证完全隔离。可在酒馆提示词检查器核对实际请求。

## 数据和编号

小说数据保存在当前浏览器、当前酒馆地址的 IndexedDB；偏好、聊天绑定、进度保存在 localStorage。换浏览器、换设备或清除网站数据需要重新导入；同浏览器同地址换角色无需重传。不要为了更新插件清除网站数据。

新版优先按完整章节切分，常见几千字章节整章保留，不重叠。超过 12000 字符的章节才按自然段分组（目标约 6000 字符），绝不在自然段中间按字数截断；单个自然段再长也完整保留。无章标题的短文本作为完整正文，长文本在自然段边界拆分。支持中文数字章标题、带空格章标题、Markdown标题及大小写英文Chapter标题。预览和AI参考都会标明完整章节，或长章的第几节。

新版导入同时保留原始全文，供以后重切。旧书保持原分段，更新插件不会擅自改它。要升级旧书：选中小说，展开「分段管理 / 小说数据」，点「更新旧书分段（重新选原 TXT）」，重新选择这本书的原始文件。更新原来的书ID，不新增重复书；各聊天进度按原文片段尽量映射到新章，预读状态和旧工具会话作废。完成后请检查预览，并用「从这里开始」调整起点。不能从旧版重叠碎片可靠恢复原文，所以不擅自拼接。

已保存全文的新版书，可直接点「按章节重新切分」，不用再次选文件。

进度按聊天隔离。旧聊天无段号时从已选章节的首段开始；未选章节则从第一段开始。每次工具调用携带阅读会话标识，换聊天或换书之后，旧会话的工具参数会被拒绝。自动推进携带当前段号和章内偏移；只允许进入已连续读取的本章后续，或本章读完后进入已读取的紧邻下一章。重复、过期和中间有未读缺口的调用会被拒绝。

文件支持 UTF-8、常见 GBK/GB18030，20 MB 上限；EPUB 请先转 TXT。只会把提供的片段发送给你当前模型服务商。

## 开发和验证

`npm test`，无需下载依赖。当前 27 项自动测试覆盖原文切分、检索、注入位置、顺序窗口、定位、预读与推进分离、书尾和重复推进、原生工具注册、窗口控件串联及跨聊天隔离。窗口串联测试模拟 DOM、IndexedDB 与酒馆接口，**不等同于真实手机或中转端到端验证**。

`bootstrap.js`、`manifest.json` 均在仓库根目录。技术交接见 `HANDOFF.md`。

主界面保留选书、当前进度、章节浏览、上一段／下一段、段号查看、完整原文预览和确认起点。导入、AI推进及阅读设置、检索记录和删除收进折叠区。预览字号16px、行距1.85，独立滚动，正文不截断。修复纵向flex布局压缩控件的原因，让主内容滚动而非所有选项挤在一屏。小说与已保存进度保留。模拟接口串联测试增加超过1200字符完整预览、浏览不推进、确认推进、回到当前进度的验证；没有真实手机布局截图验证。

## v0.2.2 默认位置调整
